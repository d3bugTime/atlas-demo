# Atlas

It's a language-independent tool for managing and migrating database schemas.

# PostgreSQL + Atlas

Core philosophy: treat the database schema as code (IaC, or Infrastructure as Code) in a declarative manner.

## Basic database extraction

### Step 1: Use a local database

You can use a PostgreSQL database even with one table

```sql
CREATE TABLE usuarios (
    id SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL
);
```

### Step 2: Generate the schema

Run the `inspect` command to extract the entire database into a single plain text file with declarative SQL formatting

```bash
atlas schema inspect \
  -u "postgres://user_name:user_password@localhost:5432/database_name?sslmode=disable" \
  --format "{{ sql . }}" \
  > schema.sql
```

Atlas consolidated the database structure in a file

```sql
-- schema.sql
CREATE TABLE "public"."users" (
  "id" serial,
  "name" character varying(100) NOT NULL,
  "email" character varying(100) NOT NULL,
  PRIMARY KEY ("id"),
  CONSTRAINT "users_email_key" UNIQUE ("email")
);
```

### Step 3: Modify the .sql file not the database

Open the schema.sql file and manually modify it to your needs, for example adding a new column (phone)

```sql
-- schema.sql
CREATE TABLE "public"."users" (
  "id" serial,
  "name" character varying(100) NOT NULL,
  "email" character varying(100) NOT NULL,
  "phone" character varying(20) NULL, -- <-- Add new column
  PRIMARY KEY ("id"),
  CONSTRAINT "users_email_key" UNIQUE ("email")
);
```

### Step 4: Simulation plan

Use the `apply` command without approving it yet, to verify which SQL commands will execute on your actual database

```bash
atlas schema apply \
  --url "postgres://user_name:user_password@localhost:5432/database_name?sslmode=disable" \
  --to "file://schema.sql" \
  --dev-url "docker://postgres/15/dev"
```

Atlas will temporarily launch a Docker container to validate the SQL syntax in schema.sql, it will calculate the differences against your actual database and display interactively

```bash
-- Checking for changes...
-- The following change will be applied to the database:

ALTER TABLE "public". "users" ADD COLUMN "phone" character varying(20) NULL;

Do you want to apply the changes? [y/N]:
```

### Step 5: Run the Apply

If everything looks correct in the plan, simply press the `y` key and then Enter

## CI/CD workflow with GitHub Actions

These requirements must be meet:

- Two environments with PostgreSQL installed to work with: the **local** and **remote**
- Both need to share the same name
  - The remote will be the receiver for the local
- A .sql file with the database structure and a .yml file as configuration to deploy
  - The .sql file was already generated in the previous section
- A GitHub repository and a Secret key already created and set

To fulfill any missing step, let's review each one:

### Step 1: Check PostgreSQL installation

```bash
# Check the server version
postgres --version
```

### Step 2: Database creation

In the previous section a local database was already created, so to create one remotely

```bash
# Connect to the remote server
ssh my-server-name

# Log into PostgreSQL
sudo -u postgres psql

# Create the database
CREATE DATABASE atlasdemodb;

# Grant privileges
GRANT ALL PRIVILEGES ON DATABASE atlasdemodb TO admin;

# To check privileges
SELECT datname AS database_name, 
       pg_get_userbyid(datdba) AS owner, 
       datacl AS privileges 
FROM pg_database 
WHERE datname = 'atlasdemodb';

# Verify and exit
# Type \l to list all databases
# Type \q to exit the PostgreSQL prompt
```

### Step 3: .sql and .yml file creation

The .sql file will be located on `atlas-demo/migrations/schema.sql`
- The content of the file is generated by the command of the previous section

The .yml file will be located on `atlas-demo/.github/workflows/atlas.yml`
- In *services*, is set a fictional credentials for the temporary database
- In *steps*, in the `url` section, the environment variable for GitHub Secrets is placed
- In *steps*, in the `dev-url` section, the link to the fictional credentials is used

```yaml
name: Deploy Schema Changes

on:
  push:
    branches: [ "main", "master" ]

jobs:
  deploy:
    runs-on: ubuntu-latest

    # Spin up a temporary PostgreSQL container to act as the dev-url
    services:
      postgres:
        image: postgres:15
        env:
          POSTGRES_PASSWORD: password
          POSTGRES_DB: dev_db
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Atlas
        uses: ariga/setup-atlas@v0

      - name: Apply Schema Declaratively
        uses: ariga/atlas-action/schema/apply@v1
        with:
          url: ${{ secrets.DATABASE_URL }}
          to: "file://migrations/schema.sql"
          dev-url: "postgres://postgres:password@localhost:5432/dev_db?sslmode=disable"
          auto-approve: "true"

```

### Step 4: GitHub Secret Key

1. Create a repository and clone it locally
2. Add the files with the folder and file structure of the previous sections
3. Before doing the commit, configure the Secret Key
  - Go to GitHub and the repository settings
  - In the left-bar `Security and quality > Secrets and variables > Actions`
  - In the Secrets tab, push the green button **New repository secret**
  - Inside fill the corresponding data:

  ```text
    Name:
    DATABASE_URL
    
    Secret:
    postgres://admin:real_password@server_ip_or_domain:5432/atlasdemodb?sslmode=require
```

4. Finally push your project and look at GitHub in the **Actions** tab
  - A list of all previous commit deployments will be shown (both successful and failed)
  - Your current commit will be deploying (with a loading icon)
  - If everything is good, a green icon will be pinned; otherwise, a red one will be
